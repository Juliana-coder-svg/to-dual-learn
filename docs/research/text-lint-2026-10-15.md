## Что следует из прогона

1. Продукт после проходов 7–14 октября в основном чист по словарным признакам. Раздражение владельца, скорее всего, вызывают признаки, которые сканер видит хуже: ритм, однотипные зачины, отсутствие конкретики, гладкие разборы наставника. Это уровни «смысл», «структура» и «ритм» из навыка, их проверяет редактор по чтению, а не регулярка.
2. Следующий шаг по тексту: прогнать через редактора реальные ответы модели (разборы, уроки), а не только шаблоны. Сканер умеет проверять файл с текстом: `node scripts/text-lint.mjs путь/к/файлу.md`.
3. Починить 7 настоящих нарушений (мелкая правка, отдельным коммитом после ревью редактора). Решить судьбу 3 цитат: внести в `scripts/text-lint-allow.json` с причиной или переписать пример.
4. Решения владельца: «в эпоху» в названии курса и «нейросеть» в юридических документах.

## Ограничения сканера

- Ловит слова, формы и простые конструкции из списков. Не ловит смысл, пустые образы, галлюцинации, водянистость, однообразие блоков (признаки с пометкой «глаза» в `ai-signs.md`).
- Тройка прилагательных и «от X до Y» определяются по форме слов; возможны ложные срабатывания на законных перечислениях.
- Контекст запрета определяется по ближайшему тексту (слова «не пиши», «запрещены», «штамп» рядом с кавычками); цитата без таких слов будет считаться нарушением.
- Проверен на Node 26.4 (на машине нет другой версии). Скрипт на чистом ESM без зависимостей, использует lookbehind и Unicode-свойства регулярок, которые есть в Node 22, но под самой Node 22 не запускался.
- Правила читаются из `references/cliches.md` и `references/ai-signs.md`. Сломанная строка правила останавливает сканер с кодом 2 и номером строки.
