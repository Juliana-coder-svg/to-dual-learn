# Скорость: замеры и причины

Дата: 8 октября 2026. Ветка `claude/quizzical-davinci-bdff85`. Замеры: `curl -w` (TTFB, 3 прогона, в таблице медиана), трассировка запросов к Supabase через `SUPABASE_TRACE=1` (см. `src/lib/supabase/server.ts` и `src/proxy.ts`: каждый вызов пишется в консоль с номером внутри рендера и временем).

## Где всё живёт

- Vercel: edge отвечает из `fra1`, функция выполняется в `iad1` (США, по умолчанию), заголовок `x-vercel-id: fra1::iad1::…`. В `vercel.json` регион не задан.
- Supabase (ref `gwpielwgaidgdjdwhdtb`): один круг запрос-ответ с моего компьютера 280–350 мс при времени самой базы 2–5 мс (`x-envoy-upstream-service-time`). Регион проекта в заголовках не виден, по задержке он далеко от Европы (похоже на Азиатско-Тихоокеанский), нужно посмотреть в Dashboard → Settings → General.
- Подпись JWT: ES256, JWKS опубликован. Значит токен можно проверять локально без запроса к Auth.

## Базовая линия (до правок)

Локально, dev-сервер на 3001, вход тестового преподавателя и студента (direct), курсов у них нет.

Прод (публичные страницы, без сессии, 3 прогона): `/` 0,36–0,79 с (первый прогон холодный), `/login` 0,38–0,55 с, redirect `/teach`, `/learn`, `/join/…` 0,35–0,45 с. Это чистая стоимость пути браузер → fra1 → функция в iad1 без единого запроса к базе.

Вывод: на каждой странице с сессией два лишних круга до Auth (proxy и страница, по ~340 мс) и ещё один до `profiles`, прежде чем начинается собственно загрузка данных. Время базы ничтожно, всё время уходит на сеть.

## Что осталось (по убыванию эффекта)

1. **Профиль параллельно с данными страницы.** `getCurrentUser` ждёт `profiles` (~300 мс) и только потом страницы идут за курсами. Есть `getCurrentUserId()` (из JWT, без сети): страницы могут брать id из него и грузить профиль и данные одним `Promise.all`. Минус ещё ~300 мс на каждой странице.
2. **`/teach`: N+1.** На каждый курс три запроса: `listLessons` (полный контент уроков), `listMaterials` (полный `content_text`), RPC студентов. Заменить одним запросом `courses?select=*,lessons(status),materials(id),enrollments(user_id)` и считать в коде.
3. **Последовательные `await`:** `teach/[courseId]/layout.tsx` (`teacherCourse` → `courseUsage`), `settings` (уроки → образцы → расход), `lessons` (уроки → материалы), `students` (3 подряд), `learn/[courseId]` (уроки → ответы → лимит), страница урока (урок → ответ → лимит → список уроков). Везде `Promise.all`.
4. **Повторные запросы layout и page:** `teacherCourse`/`studentCourse` и `getCourse` вызываются и в layout, и в page. Обернуть в React `cache()`.
5. **Лишние колонки:** `listMaterials` ради количества тянет `content_text`; `listLessons` ради следующего урока тянет весь `content`. Добавить `listMaterialSummaries` (id, filename, kind, char_count, created_at) и `listLessonSummaries` (id, title, position, status).
6. **Регион функции Vercel.** Добавить в `vercel.json` `"regions": ["<ближайший к Supabase>"]`, когда известен регион проекта. Сейчас iad1 и, судя по задержкам, база в другом полушарии.
7. **Индексы.** Все запросы страниц уже покрыты индексами из `0001_init.sql`, время базы 2–5 мс. Новая миграция не нужна, пока не вырастут данные.
8. **Холодный старт Vercel:** первый ответ на проде +400 мс. Отдельно не трогал.

## Что мешает дозамерить

Страницы курса (`/teach/<id>` и дальше, `/learn/<id>`, урок) не замерены: у тестовых аккаунтов `speed-teacher@todual.ru` и `speed-student@todual.ru` нет курса, а создание курса-примера в общей базе Supabase из скрипта было заблокировано режимом разрешений. Нужно либо разрешение создать курс-пример под тестовым преподавателем, либо пройти это руками в браузере на localhost:3001 и повторить `scratchpad/local-bench.sh`.
