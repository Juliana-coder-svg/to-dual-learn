# Скорость: замеры и причины

Дата: 8 октября 2026. Ветка `claude/quizzical-davinci-bdff85`. Замеры: `curl -w` (TTFB, 3 прогона, в таблице медиана), трассировка запросов к Supabase через `SUPABASE_TRACE=1` (см. `src/lib/supabase/server.ts` и `src/proxy.ts`: каждый вызов пишется в консоль с номером внутри рендера и временем).

## Где всё живёт

- Vercel: edge отвечает из `fra1`, функция выполняется в `iad1` (США, по умолчанию), заголовок `x-vercel-id: fra1::iad1::…`. В `vercel.json` регион не задан.
- Supabase (ref `gwpielwgaidgdjdwhdtb`): один круг запрос-ответ с моего компьютера 280–350 мс при времени самой базы 2–5 мс (`x-envoy-upstream-service-time`). Регион проекта в заголовках не виден, по задержке он далеко от Европы (похоже на Азиатско-Тихоокеанский), нужно посмотреть в Dashboard → Settings → General.
- Подпись JWT: ES256, JWKS опубликован. Значит токен можно проверять локально без запроса к Auth.

## Базовая линия (до правок)

Локально, dev-сервер на 3001, вход тестового преподавателя и студента (direct), курсов у них нет.

| Страница | TTFB локально | Запросов к Supabase | Что происходит |
|---|---|---|---|
| `/` без сессии | 0,03 с | 0 | |
| `/login` без сессии | 0,03 с | 0 | |
| `/` с сессией (redirect) | 1,01 с | 3 | proxy `getUser` 340 мс → page `getUser` 340 мс → `profiles` 290 мс, всё последовательно |
| `/login` с сессией | 1,05 с | 3 | то же |
| `/teach` (0 курсов) | 1,35 с | 4 | + `courses` 300 мс; с N курсами ещё 3 запроса на курс (уроки с контентом, материалы с текстом, RPC студентов) |
| `/learn` | 1,33 с | 5 | + `enrollments`, `flashcards` (параллельно) |
| `/learn/review` | 1,36 с | 4 | |
| `/learn/history` | 1,31 с | 4 | |
| `/teach/<id>`, `/lessons`, `/settings`, `/learn/<id>`, урок | не замерено | | нужен курс у тестового аккаунта, см. ниже |

Прод (публичные страницы, без сессии, 3 прогона): `/` 0,36–0,79 с (первый прогон холодный), `/login` 0,38–0,55 с, redirect `/teach`, `/learn`, `/join/…` 0,35–0,45 с. Это чистая стоимость пути браузер → fra1 → функция в iad1 без единого запроса к базе.

Вывод: на каждой странице с сессией два лишних круга до Auth (proxy и страница, по ~340 мс) и ещё один до `profiles`, прежде чем начинается собственно загрузка данных. Время базы ничтожно, всё время уходит на сеть.

## Что сделано

### 1. Проверка сессии локально вместо похода в Auth

`src/proxy.ts` и `src/lib/auth/session.ts`: `auth.getUser()` заменён на `auth.getClaims()`. Подпись токена проверяется по JWKS (ключи ES256 кэшируются в процессе на 10 минут), протухший токен по-прежнему обновляется через refresh. Два сетевых вызова на страницу ушли.

| Страница | Было | Стало |
|---|---|---|
| `/` с сессией | 1,01 с | 0,33 с |
| `/teach` (0 курсов) | 1,35 с | 0,68 с |
| `/learn` | 1,33 с | 0,75 с |
| `/learn/review` | 1,36 с | 0,65 с |
| `/learn/history` | 1,31 с | 0,64 с |

Проверки: type-check и lint зелёные.

### 2. Профиль и курс параллельно, один поиск курса на layout и page

`src/lib/auth/access.ts`: `teacherCourse` и `studentCourse` обёрнуты в React `cache()` (layout и page маршрута `/teach/[courseId]` вызывали их дважды) и грузят профиль, курс и запись на курс одним `Promise.all`. `src/lib/auth/session.ts`: `requireUserId()` отдаёт id из JWT без сети, чтобы страница не ждала профиль перед своими запросами.

### 3. Все запросы страницы одним кругом, выборки без лишних колонок

- Все страницы преподавателя и студента собирают данные через `Promise.all`: `/teach/[courseId]` (layout: доступ ∥ расход), материалы, уроки, настройки, студенты, чат, документы, проверка работ, правка урока; `/learn`, `/learn/[courseId]`, урок, повторение, история.
- `/teach`: вместо 1 + 3 запроса на курс один `courses?select=*,lessons(status),materials(id),enrollments(user_id)` (`listCourseSummariesByOwner`).
- `/learn`: вместо 2 + 3 на курс четыре параллельных запроса: профиль, курсы с уроками (`listCoursesForStudentWithLessons`), карточки, ответы по всем курсам (`progressByCourse`).
- Там, где нужны только заголовки и статусы, `listLessonSummaries` вместо `listLessons` с контентом; `countMaterials` вместо `listMaterials` с полным `content_text`.
- `courseProgress` считает дневной лимит из уже выбранных ответов вместо отдельного RPC `count_lessons_started_today` (RPC остаётся для `/api/evaluate`).

|---|---|---|---|---|
| `/` с сессией | 1,01 с | 0,33 с | 0,41 с | 3 → 1 |
| `/teach` (0 курсов) | 1,35 с | 0,68 с | 0,43 с | 4 → 2 параллельно (с N курсами было 4 + 3N) |
| `/learn` (0 курсов) | 1,33 с | 0,75 с | 0,43 с | 5 → 4 параллельно (с N курсами было 5 + 3N) |
| `/learn/review` | 1,36 с | 0,65 с | 0,41 с | 4 → 2 параллельно |

Нижняя граница теперь один круг до базы (~300 мс с моего компьютера); дальше ускорять можно только переносом функции ближе к базе. Страницы курса по коду стали устроены так же (один круг вместо 3–5 последовательных), но цифр по ним нет, см. ниже.

Проверки: `type-check`, `lint`, `build` зелёные.

## Регион функции Vercel

Проверка на проде: маршрут без базы (`/login`) отвечает за 0,37–0,45 с, маршрут с одним запросом к Auth (`/auth/callback` с неверным token_hash) за 0,56–0,66 с. То есть круг от функции в iad1 до Supabase около 200 мс: база не в США и не в Европе (из Европы было бы ~90 мс), а в Азиатско-Тихоокеанском регионе. С моего компьютера круг 290–350 мс, что тоже укладывается.

Что сделать: посмотреть регион проекта в Supabase (Dashboard → Project Settings → General → Region) и добавить в `vercel.json` строку `"regions": ["sin1"]` для Singapore (`hnd1` Tokyo, `syd1` Sydney, `bom1` Mumbai, `icn1` Seoul). Для пользователя в России путь браузер → edge → функция удлинится на ~70 мс, зато каждый запрос к базе подешевеет с 200 мс до 5–60 мс; при одном круге на страницу это выигрыш, при двух и больше (все API-маршруты с оценкой и генерацией делают несколько запросов) заметный.

## Что осталось

1. **Регион Vercel** (выше): одна строка в `vercel.json` после подтверждения региона Supabase.
2. **Замеры страниц курса**: `/teach/<id>`, `/lessons`, `/settings`, `/learn/<id>`, урок. Нужен курс у тестового преподавателя.
3. **Индексы.** Все запросы страниц уже покрыты индексами из `0001_init.sql`, время базы 2–5 мс. Новая миграция не нужна, пока не вырастут данные.
4. **Холодный старт Vercel:** первый ответ на проде +0,4–2 с (замерено 0,79 с на `/`, 1,29 с на `/login`, 2,5 с на `/auth/callback`). Снижать размером серверного бандла; отдельно не трогал.
5. **API-маршруты** (`/api/evaluate`, `/api/lessons/*`, `/api/chat`): там всё ещё по несколько последовательных запросов перед вызовом модели; на фоне 10–170 с самой модели это не главное, но после переноса региона их тоже стоит собрать в `Promise.all`.

## Как повторить замеры

```bash
SUPABASE_TRACE=1 PORT=3001 npm run dev
```

В консоли на каждый запрос: `[proxy] /путь getClaims N ms` и `[sb:user] #n METHOD /rest/v1/... N ms`; строка Next `GET /путь 200 in N ms` даёт время страницы. Время ответа снаружи: `curl -s -o /dev/null -b cookies.txt -w "%{time_starttransfer}\n" http://localhost:3001/teach`.
